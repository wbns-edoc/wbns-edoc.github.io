# ข้อกำหนดผู้อนุมัติใบลา — ยืนยันจากเจ้าของระบบ

สถานะ: ข้อกำหนด workflow ที่เจ้าของระบบยืนยันแล้ว; การผูกบัญชีผู้ใช้และหลักฐานมอบอำนาจยังเป็น release gate ก่อนเปิด Production

## อำนาจอนุมัติที่ยืนยันแล้ว

**ผู้อำนวยการโรงเรียนเป็นผู้อนุมัติขั้นสุดท้าย**

1. เมื่อโรงเรียนมีรองผู้อำนวยการ: คำขอเข้าสู่รองผู้อำนวยการเพื่อตรวจพิจารณาก่อน จากนั้นส่งต่อผู้อำนวยการเพื่ออนุมัติขั้นสุดท้าย
2. เมื่อโรงเรียนไม่มีรองผู้อำนวยการ: ส่งคำขอตรงถึงผู้อำนวยการ และผู้อำนวยการอนุมัติหรือไม่อนุมัติได้โดยตรง การไม่มีรองผู้อำนวยการต้องไม่ทำให้ workflow ติดขัด
3. เมื่อผู้อำนวยการไม่อยู่: รองผู้อำนวยการอาจอนุมัติแทนได้เฉพาะเมื่อมีหลักฐานการไม่อยู่/การมอบหมายหรือมอบอำนาจที่ตรวจสอบย้อนหลังได้ ระบบต้องปฏิเสธการอนุมัติแทนหากไม่มีหลักฐานดังกล่าว
4. System Admin มีหน้าที่ตั้งค่าและตรวจสอบหลักฐาน ไม่ได้รับอำนาจอนุมัติใบลาโดยอัตโนมัติเพียงเพราะเป็น System Admin

## การบังคับใช้ทางเทคนิค

- ตรวจสิทธิ์ที่ RPC/ฐานข้อมูล ไม่พึ่งการซ่อนหรือแสดงปุ่มใน frontend
- เก็บผู้อนุมัติปัจจุบัน ขั้นอนุมัติ ผู้ตัดสินใจ เวลา เหตุผล และหลักฐานที่เกี่ยวข้องใน audit trail
- ป้องกันการอนุมัติคำขอตนเอง
- การเปลี่ยนผู้ดำรงตำแหน่งหรือการตั้งค่ามี/ไม่มีรองผู้อำนวยการต้อง invalidate การยืนยัน authority เดิม และต้องยืนยันใหม่ก่อนรับคำขอ
- เมื่อไม่มีรองผู้อำนวยการ route ที่ยืนยันแล้วต้องมี Director เป็นผู้อนุมัติคนเดียวในขั้นสุดท้าย
- เมื่อมีรองผู้อำนวยการ route ปกติต้องเป็น Vice Director review → Director final approval
- การอนุมัติแทนผู้อำนวยการต้องตรวจหลักฐานเป็นรายกรณี ไม่ใช้เพียง flag เปิด/ปิดเป็นหลักฐาน

## สถานะการเปิดใช้จริง

ข้อกำหนดอำนาจอนุมัติข้างต้นถือว่ายืนยันแล้ว ไม่ต้องถามเจ้าของระบบซ้ำว่าใครเป็นผู้อนุมัติ อย่างไรก็ตาม ก่อนเปิด Production ต้องผูกบัญชี auth/profile ของผู้อำนวยการกับตำแหน่งจริงโดยผู้ดูแลที่ได้รับอนุญาต และบันทึกเอกสารอ้างอิงที่ตรวจสอบได้ในระบบ ห้ามสร้างบัญชีหรืออ้างเอกสารแต่งตั้งขึ้นเอง

การอนุมัติ workflow ไม่ถือเป็นการอนุมัติ policy วันลา ปฏิทินวันทำงาน หรือการยืนยันค่าใช้จ่าย Production; release gates เหล่านั้นยังต้องผ่านแยกกัน
