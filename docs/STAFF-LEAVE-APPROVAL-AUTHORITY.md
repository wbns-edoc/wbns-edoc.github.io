# ข้อกำหนดผู้อนุมัติใบลา — ยืนยันจากเจ้าของระบบ

สถานะ: workflow ที่เจ้าของระบบยืนยันแล้ว; การมอบหมายผู้อนุมัติแทนและการทดสอบยังเป็น release gate

## เส้นทางปกติ
- ผู้ยื่นคำขอ → ผู้อำนวยการโรงเรียนโดยตรง
- ไม่มีขั้นรองผู้อำนวยการในเส้นทางปกติ
- ผู้อำนวยการเป็นผู้อนุมัติ/ไม่อนุมัติขั้นสุดท้าย

## กรณีผู้อำนวยการไม่สามารถปฏิบัติหน้าที่
- System Admin เป็นผู้กำหนดบัญชีบุคลากรที่มีสิทธิ์และมอบหมายให้เป็นผู้อนุมัติแทน
- ผู้รับมอบหมายอาจเป็นบุคลากรคนใดก็ได้ที่เป็นบัญชีบุคลากรที่ active และผ่านเงื่อนไข eligibility ที่ระบบกำหนด ไม่จำกัดเฉพาะรองผู้อำนวยการ
- การมอบหมายต้องระบุช่วงวันและเวลาเริ่ม/สิ้นสุด เหตุผล และเอกสาร/เลขอ้างอิงอำนาจ
- ต้องบันทึกผู้กำหนด วันเวลาที่กำหนด ประวัติการแก้ไข/เพิกถอน และผู้รับมอบหมาย
- เมื่อส่งคำขอ ต้อง snapshot ผู้อนุมัติและข้อมูลการมอบหมายที่มีผล ณ เวลาส่งคำขอ คำขอเดิมต้องไม่เปลี่ยนผู้อนุมัติเมื่อมีการแก้การมอบหมายภายหลัง
- ห้ามผู้รับมอบหมายอนุมัตินอกช่วงเวลาที่มอบหมาย หรือหลังถูกเพิกถอน; ต้อง fail closed และไม่เปลี่ยนผู้อนุมัติย้อนหลังอย่างเงียบ ๆ
- System Admin ไม่ได้เป็นผู้อนุมัติโดยอัตโนมัติ เว้นแต่ได้รับมอบหมายอย่างชัดแจ้ง และไม่ควรอนุมัติคำขอด้วยสิทธิ์ Admin เพียงอย่างเดียว

## การบังคับใช้ทางเทคนิค
- ตรวจสิทธิ์ใน RPC/ฐานข้อมูล ไม่พึ่งการซ่อนปุ่มใน frontend
- เก็บผู้อนุมัติ ขั้นอนุมัติ ผู้ตัดสินใจ เวลา เหตุผล และหลักฐานใน audit trail
- ป้องกันการอนุมัติคำขอตนเอง
- การเปลี่ยนหรือเพิกถอนการมอบหมายมีผลกับคำขอใหม่; คำขอที่ส่งแล้วใช้ immutable snapshot โดยตรวจสถานะการอนุมัติและข้อกำหนดความปลอดภัยที่เกี่ยวข้อง
- การมอบหมายต้องมี exclusion/locking ป้องกันช่วงเวลาซ้อนที่ทำให้มีผู้อนุมัติหลายคนโดยไม่ตั้งใจ
- ถ้าไม่มีผู้อำนวยการที่ active และไม่มี acting delegation ที่ valid ให้ปิดการยื่นคำขอแบบ fail closed

## Release gate
ต้องมี migration, RPC, RLS, UI สำหรับ System Admin, audit trail, immutable route snapshot และ regression tests ครอบคลุมการมอบหมาย/หมดอายุ/เพิกถอน/ช่วงเวลาซ้อน/การเปลี่ยนผู้อนุมัติหลังส่งคำขอ ก่อนเปิด Production

การยืนยัน workflow ไม่ถือเป็นการยืนยันนโยบายสิทธิวันลา ปฏิทินวันทำงาน หรือค่าใช้จ่าย Production; gates เหล่านั้นต้องผ่านแยกกัน
