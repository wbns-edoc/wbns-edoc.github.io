# ข้อกำหนดอำนาจอนุมัติใบลา — โรงเรียนวัดบึงน้ำใส

สถานะ: ข้อกำหนดออกแบบ; ห้ามใช้เป็นคำสั่งเปิด Production โดยลำพัง  
วันที่บันทึก: 21 ตุลาคม 2569

## ข้อเท็จจริงที่เจ้าของระบบยืนยัน
- บทบาทผู้อนุมัติที่กำหนดไว้ในระบบ ได้แก่ ผู้อำนวยการโรงเรียนและรองผู้อำนวยการโรงเรียน
- ปัจจุบันโรงเรียนไม่มีผู้ดำรงตำแหน่งรองผู้อำนวยการโรงเรียน
- ต้องคงนิยามบทบาทรองผู้อำนวยการไว้ในระบบ แต่ห้ามถือว่าบทบาทนั้นมีผู้รับงานหรือผู้อนุมัติที่ใช้งานได้จริง
- การกำหนดสิทธิ์ใน RBAC ไม่ใช่หลักฐานว่าบุคคลใดได้รับแต่งตั้งหรือมอบอำนาจให้อนุมัติคำขอใดได้

## พฤติกรรมที่ต้องบังคับใช้
1. ก่อนส่งคำขอ ต้อง resolve ผู้อนุมัติจากบทบาทและการมอบหมายที่ตรวจสอบแล้ว โดยตรวจผู้ใช้ที่ active และอำนาจที่เกี่ยวข้องกับประเภทบุคลากร/คำขอ
2. ห้ามสร้างงานรออนุมัติที่ส่งถึงตำแหน่งรองผู้อำนวยการซึ่งไม่มีผู้ดำรงตำแหน่ง ห้ามสร้างผู้รับมอบหมายสมมติ และห้ามมอบสิทธิ์รองผู้อำนวยการให้ผู้อำนวยการหรือบุคคลอื่นโดยอัตโนมัติ
3. ห้ามเปิดเส้นทางผู้อำนวยการอนุมัติโดยตรงจนกว่าจะตรวจเอกสารทางการและคำสั่งมอบอำนาจที่ใช้กับโรงเรียนแล้ว การไม่มีรองผู้อำนวยการเป็นข้อเท็จจริงด้านบุคลากร ไม่ใช่การมอบอำนาจโดยตัวมันเอง
4. หากตรวจไม่พบผู้อนุมัติที่มีอำนาจ ให้เก็บคำขอและประวัติไว้ในสถานะที่มองเห็นได้ เช่น `blocked_approver_resolution` และแจ้งผู้ดูแลที่ได้รับอนุญาตให้แก้การกำหนดเส้นทาง โดยการแจ้งเตือนไม่ได้เพิ่มสิทธิ์อนุมัติ
5. ทุกการเปลี่ยนสถานะต้องทำผ่านฟังก์ชันฝั่งฐานข้อมูล/server ที่ตรวจสิทธิ์และสถานะเดิมแบบ atomic; ห้ามให้ client เขียนสถานะหรือข้อมูลผู้อนุมัติโดยตรง
6. ป้องกัน self-approval แม้ผู้ร้องมีบทบาทผู้อนุมัติอื่นด้วย
7. บันทึก actor, action, timestamp, เหตุผล และหลักฐานการมอบอำนาจที่ใช้ในแต่ละการตัดสินใจ
8. แจ้งเตือนเฉพาะผู้อนุมัติที่ resolve และผ่านการตรวจสิทธิ์แล้ว ไม่แจ้งตำแหน่งที่ว่างเหมือนมีคนรับงาน

## แหล่งอ้างอิงและข้อจำกัด
- สำนักงาน ก.ค.ศ. ว 14/2568 ลงวันที่ 3 เมษายน 2568 เรื่องผู้มีอำนาจพิจารณาหรืออนุญาตการลาของข้าราชการครูและบุคลากรทางการศึกษา: https://circular.otepc.go.th/v1_t_circualr_book_view.php?editid1=657
- รายการหนังสือเวียนทางการระบุสถานะปกติและอ้างถึง ว 42/2555 ซึ่งถูกยกเลิกแล้ว
- ต้องตรวจตารางอำนาจในเอกสารฉบับเต็ม รวมทั้งคำสั่ง/การมอบอำนาจของหน่วยงานต้นสังกัด และความครอบคลุมบุคลากรทุกประเภทในโรงเรียนก่อนกำหนด workflow จริง
- ห้ามอนุมานว่ากฎสำหรับข้าราชการครูฯ ใช้กับพนักงานราชการ ครูอัตราจ้าง หรือบุคลากรประเภทอื่นโดยอัตโนมัติ

## Release gate
ยังไม่อนุญาต Production workflow, migration, หรือการแก้ RBAC จนกว่าจะมีหลักฐานตรวจสอบอำนาจอนุมัติ, ยืนยัน role/permission codes และผู้ได้รับมอบหมายจริง, ทดสอบ migration replay/RLS/workflow ใน environment แยก, ผ่าน CI และได้รับอนุมัติปล่อยใช้งานอย่างชัดแจ้ง
