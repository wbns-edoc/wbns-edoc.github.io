# Forward-Only Remediation Plan: Workflow RPC Exposure
**Project:** ระบบสารบรรณอิเล็กทรอนิกส์ โรงเรียนวัดบึงน้ำใส  
**Date:** 2026-10-10  
**Status:** Remediation specification; NOT an executable migration and NOT applied to Production

## Confirmed Production blocker

A read-only catalog query confirmed these public functions are currently SECURITY DEFINER and executable by authenticated:
- public.assign_document(uuid,uuid,text,timestamptz)
- public.set_document_deadline(uuid,uuid,timestamptz,timestamptz)
- public.update_document_status(uuid,document_status,text)

The query confirmed anon cannot execute those functions. That does not fix SECURITY DEFINER exposure to authenticated callers. Matching SECURITY DEFINER implementations exist in private. public.create_approval and public.decide_approval were observed as SECURITY INVOKER.

## Safe remediation shape

Do not run SQL in this document. Generate a proper timestamped migration with the Supabase CLI in a local checkout, test it against a disposable local database, and submit it for review. Restore the public API functions as SECURITY INVOKER wrappers calling only the matching private implementation.

Representative shape; verify live signatures, defaults, schema usage, grants, and caller context before use:

```sql
create or replace function public.assign_document(
 p_document_id uuid, p_assignee_id uuid, p_instructions text default null, p_due_at timestamptz default null
) returns uuid language sql security invoker
set search_path = pg_catalog, public, private
as $$ select private.assign_document($1, $2, $3, $4) $$;

create or replace function public.set_document_deadline(
 p_document_id uuid, p_assigned_to uuid, p_due_at timestamptz, p_reminder_at timestamptz default null
) returns uuid language sql security invoker
set search_path = pg_catalog, public, private
as $$ select private.set_document_deadline($1, $2, $3, $4) $$;

create or replace function public.update_document_status(
 p_document_id uuid, p_to_status public.document_status, p_reason text default null
) returns boolean language sql security invoker
set search_path = pg_catalog, public, private
as $$ select private.update_document_status($1, $2, $3) $$;
```

Before use, confirm:
1. authenticated has USAGE on private if the invoker wrapper needs it.
2. authenticated has EXECUTE only on approved public wrappers; anon/PUBLIC do not.
3. Private implementations independently validate auth.uid() and the relevant permission.
4. Live signatures and defaults exactly match; do not alter application RPC contracts.
5. Catalog regression checks assert public assign_document, set_document_deadline, update_document_status, create_approval, and decide_approval are not SECURITY DEFINER.
6. Verify behavior and grants in a local database; do not test by executing against Production.

## Separate mandatory fix: last System Admin protection

The live public.admin_remove_user_role(uuid,uuid) is SECURITY DEFINER and deletes a role assignment after a generic role/user management permission check, with no visible guard against removing the last active System Admin. It is callable by authenticated, not anon.

A separate forward-only migration must identify the canonical System Admin role via a verified stable identifier/approved exact mapping; serialize concurrent removals; reject removing or deactivating the final active System Admin; and prevent accidental self-lockout unless another active System Admin remains. Test sequential and concurrent cases only in a disposable database. Never test destructive cases against the only Production admin.

## Required release tests

- Catalog regression: the five public workflow RPCs listed above are SECURITY INVOKER.
- ACL regression: anon cannot execute them; authenticated can execute only approved wrappers.
- Behavior tests: wrappers delegate correctly and reject unauthenticated callers.
- Department-isolation tests for direct table access, RPC, Edge Function, and attachments after scope enforcement is implemented.
- Last-admin removal/deactivation is rejected under sequential and concurrent attempts.
- Fresh migration replay and upgrade-from-snapshot both pass.

## Why no Production change was made

Production migration history and repository SQL files are not reconciled, and there is no isolated Supabase environment to validate a new migration. Do not create paid resources. Keep this as a remediation specification until the migration is generated by the CLI, tested locally, reviewed, backed up, and explicitly approved.
